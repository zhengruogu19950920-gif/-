# 改动工作流

## 修改分类

### A 类：设定层修改
- 定义：修改世界设定、人物背景、历史事件等基础设定
- 影响：可能波及多个章节和文件
- 流程：先更新设定文件 → 再逐章同步 → 最后校验

### B 类：文本层修改
- 定义：修改具体段落、句子、用词
- 影响：通常只限当前章节
- 流程：定位 → 修改 → 自检

### C 类：格式层修改
- 定义：文件名、目录结构、脚注格式等
- 影响：可能影响引用链接
- 流程：修改 → 扫描所有引用 → 批量更新

## 修改执行流程

```
1. PRE-CHECK（修改前检查）
   ├── 读取当前文件
   ├── 扫描关联文件
   └── 列出影响范围

2. EXECUTE（执行修改）
   ├── 主文件修改
   ├── 关联文件同步
   └── 全局文件更新（如需要）

3. POST-CHECK（修改后校验）
   ├── 自洽性校验
   ├── 跨章校验
   └── 红线校验
```

## 不该做的（反模式）

- ❌ 只改一个文件，忽略关联文件
- ❌ 在没有确认权威口径的情况下做"统一"
- ❌ 顺手改与本次任务无关的内容
- ❌ 把讨论期的口径直接写成定稿
- ❌ 修改后不更新伏笔清单/进度总纲

## 批量修改注意事项

当需要批量替换某个称法时（如"软鞭" → "双鞭"）：

1. 先确认权威口径（从设定文件或硬约束中确认正确称法）
2. 全局搜索所有出现位置
3. 逐处判断：是笔误（直接改）还是上下文需要保留（不改）
4. 执行批量替换
5. 逐处复核替换结果
6. 记录修改日志
