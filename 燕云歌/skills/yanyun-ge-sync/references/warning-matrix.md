# 预警矩阵

## 严重级别定义

| 级别 | 图标 | 含义 | 响应要求 |
|------|------|------|---------|
| 1 | 🔴 | 触犯硬约束红线 | 立即停止当前操作，优先修正 |
| 2 | 🟠 | 同一事实在多个文件中矛盾 | 暂停推进，确认权威口径后统一 |
| 3 | 🟡 | 脚注重复/格式不统一/引用断裂 | 正常处理，不阻塞主流程 |
| 4 | 🔵 | 潜在风险/建议改进 | 记录，择机处理 |

## 常见预警场景及应对

### 🔴 等级 1：硬约束红线

| 场景 | 检查方式 | 应对 |
|------|---------|------|
| 正文中出现了"桑维翰就是嵩阳"的明写 | 搜索"桑维翰"+"嵩阳"同段出现 | 改为隐写或删除 |
| 944 年前赵则平叫桑维翰"师父" | 检查时间线 + 称呼 | 修改称呼 |
| 928 年场景中石敬瑭被称为"陛下" | 检查年份 + 称谓 | 改为"节度使"等符合历史的称谓 |
| 刘赟兵器写成"软鞭/软节鞭" | 全局搜索"软鞭" | 改为"双鞭" |

### 🟠 等级 2：事实矛盾

| 场景 | 检查方式 | 应对 |
|------|---------|------|
| 同一地名在两个文件中称法不同 | 全局搜索该地名 | 确认历史正确称法后统一 |
| 人物年龄在前后章对不上 | 核对时间线 | 以设定文件中的出生年份推算 |
| 同一事件的发生时间描述不同 | 核对时间线 + 章节 | 以总纲中锁定的时间线为准 |
| 章节结尾与下章开头物理位置不对 | 检查章节接口 | 修正物理衔接 |

### 🟡 等级 3：格式/引用问题

| 场景 | 检查方式 | 应对 |
|------|---------|------|
| 脚注重复（同一名词注了多次） | 扫描全项目脚注 | 保留首次出现处，删除重复 |
| Wiki-link 断裂 | 检查所有 `[[link]]` 是否指向存在的文件 | 更新链接或创建缺失文件 |
| 章节编号不一致 | 核对总纲中的章节编号 | 统一为总纲口径 |
| Frontmatter 字段缺失 | 检查关键文件的 tags/aliases | 补充必要字段 |

### 🔵 等级 4：潜在风险

| 场景 | 检查方式 | 应对 |
|------|---------|------|
| 新设定的命名可能与其他设定冲突 | 搜索相似命名 | 确认后记录，择机统一 |
| 伏笔清单中的"待回收"项超过 5 章未处理 | 扫描伏笔清单 | 提醒作者关注 |
| 某章节过长（可能影响阅读节奏） | 统计各章节字数 | 建议拆分或收紧 |
| 文件引用路径使用了绝对路径 | 搜索 "C:" 或 "E:" | 改为相对路径 |

## 预警触发后的标准响应

```
1. 识别：确认预警级别和场景
2. 定位：找到所有受影响的文件
3. 决策：根据级别决定处理优先级
    - 🔴：立即处理
    - 🟠：暂停当前推进，处理后继续
    - 🟡：不阻塞，正常处理
    - 🔵：记录，不阻塞
4. 执行：按"最小同步"原则修改
5. 校验：三级校验（自洽 → 跨章 → 红线）
6. 记录：在修改文件中添加同步标记
```
